# Trusted project and loopback control boundary: threat model

Status: accepted (2026-08-31, [Task: threat-model the trusted-project and localhost control boundary](https://github.com/wojtekpiskorz/astroix/issues/199); recorded by lane A1, [#210](https://github.com/wojtekpiskorz/astroix/issues/210)). An architecture threat model — mandatory controls for the rewrite, not a claim that any of it is implemented.

## Context

After the product contract ([#205](https://github.com/wojtekpiskorz/astroix/issues/205)) and runtime topology ([#202](https://github.com/wojtekpiskorz/astroix/issues/202)), the rewrite needed one settled enumeration of remote, accidental-authority, cross-project, and failure paths around the Astroix runtime — explicitly refusing to design a sandbox for malicious registered projects (the trust premise) while refusing to grant Astroix-wide authority on the back of that trust. Exact registry, session, and authorization mechanics were left to [#204](https://github.com/wojtekpiskorz/astroix/issues/204) (ADR-0006); packaged crash/quit cases to [#201](https://github.com/wojtekpiskorz/astroix/issues/201).

## Decision

### Boundary

The registered Astro project is developer-trusted executable code: its config, integrations, dependencies, inline scripts, and external scripts may run as the developer, and its same-origin browser JavaScript may inspect the app shell through direct DOM access. The disposable project plane is a failure and lifecycle boundary, not a sandbox. That premise grants nothing app-wide — five categories govern:

1. **Accepted project capability**: load the registered project's real config and integrations; inspect its typed Content, route, and style model; use direct same-origin DOM access; edit only issued Content or mapped-CSS resources for the active activation.
2. **Remote or unregistered input**: rejected before control dispatch or proxying unless it reaches a loopback socket under the exact active virtual host and satisfies the browser-origin constraints, protocol version, non-reusable active-session binding, and request authorization of ADR-0006. Host, Origin, and Fetch Metadata are forgeable by a raw local client and are not authorization by themselves. The mechanism defends remote, unregistered, and accidental callers — it is not claimed as isolation from deliberately malicious same-user software, which already has the developer's filesystem and process authority.
3. **Stale or cross-project work**: every command, response, query result, event stream, resource handle, and queued side effect is bound to the activation that created it. A switch revokes the old lease and closes its connections first; the server checks activation and authority at dispatch and again immediately before a write. A request never resolves its target from mutable global active state after acceptance.
4. **Failure containment**: a worker, managed Astro server, composition Vite server, renderer, inspection, control-plane, or app failure revokes the lease and closes proxy, SSE, and HMR sockets first; rejects new inspection and edit work; aborts underlying in-flight work; closes the composition server, runners, watchers, and timers; terminates and reaps exact child handles and descendants; and records an honest bounded cleanup report. No automatic project-plane restart.
5. **Operations that do not exist**: no arbitrary path read or write, shell command, generic child-process control, PID-based kill, arbitrary module evaluation, raw Vite handle, request-selected proxy target, project-page registry mutation, generic native picker bridge, raw Electron IPC, unvalidated external-open operation, or git operation.

### Mandatory controls

- **Listener and routing**: bind the control listener only to loopback and acquire the actual socket before publishing an origin. Route only the neutral launcher or one exact active project hostname. Reject unknown, malformed, duplicate, trailing-dot, stale, and DNS-rebinding Host values; reject absolute-form requests, CONNECT, ambiguous encoded paths, and any reserved `/__astroix/` path that does not match a known route. The active ready descriptor — never request input — selects the sole upstream.
- **`.localhost` is routing, not authority** (RFC 6761 §6.3 gives it loopback behavior; it authorizes nobody). Reusable authority never goes in URLs or logs. WebSocket upgrades independently validate Host, Origin, route, authorization, activation, and subprotocol (RFC 6455 makes Origin validation a server decision); SSE gets its own validation and limits.
- **Resource handles**: opaque, issued only from Astroix's own Content and style discovery, bound to canonical project identity, resource kind, allowed operation, activation, and freshness state; containment and symlink-policy checks repeat at use time; every write requires a freshness/conflict precondition; a new file's canonical parent is validated; a renderer-chosen path is never accepted. (Exact representation: ADR-0006 grants.)
- **One registry writer, one active session**: versioned, schema-validated, atomic and recoverable registry writes; restrictive permissions; canonical identity; explicit duplicate policy; corrupt-state quarantine — a corrupt or future-schema registry opens the neutral launcher instead of guessing.
- **Child processes**: spawn exact executables with argument arrays, canonical cwd, `shell: false`, and a minimal environment with no app-private authorization material. Hold exact sibling child handles and the composition-server handle; never discover children by PID.
- **Electron hardening**: no generic native bridge; `nodeIntegration` off, context isolation, sandboxing, and `webSecurity` on; validate the exact sender for any narrowly unavoidable IPC; deny permissions, popups, and webviews; allow only the expected launcher or active app main-frame navigation; disable editing when the canvas leaves the active project origin; use the Electron single-instance lock **as well as** control-plane registry exclusivity (command-line launches on macOS can bypass the OS's ordinary single-instance behavior).
- **Limits and output hygiene**: operation-specific request, response, file, schema, route-count, event, connection, and log limits; exact content types and strict schemas; unknown fields rejected; errors and cleanup output bounded; raw paths, PIDs, ports, child environment, and authorization material never appear in public responses, events, errors, logs, or reports.

### Oracle findings that must not carry forward

The integration is a migration input, not a compatibility contract: its request guard accepting missing `Sec-Fetch-Site`; client-supplied file paths with lexical-only confinement and an optional expected hash; and route timeouts that reject the caller without cancelling the work. The parent runtime needs abortable work and one recursive stop contract.

## Consequences

- These controls are mandatory architecture requirements; their implementation status is proved by the lanes that own the mechanics (ADR-0006 registry/session/authority; ADR-0008 packaged lifecycle).
- The mandatory negative-test matrix binds those lanes' evidence: listener/router negatives (non-loopback reachability, malformed/duplicate/trailing-dot/unknown/stale Host, rebinding domain, Origin variants, CSRF forms, absent/wrong/stale activation or authorization, no CORS opt-in, launcher using project routes, unknown key, encoded reserved paths, request-selected target, foreign listener collision); WebSocket/SSE negatives; resource/payload negatives (stale/cross-project/wrong-kind handles, missing freshness, symlink escapes and swaps, hardlinks, malformed/oversized payloads, no implementation detail in any output); switching races (A-to-B, A-to-B-to-A, slow inspection, queued auto-write, in-flight responses, open SSE/HMR, stale query results, old DOM selection, stale menu actions, activation failure, stop-during-start, concurrent activation, no old write commits under the current activation); registry and zero-injection snapshots (byte/metadata across register, start, inspect, switch, stop, plane crash, control crash, quit — only explicit Content/mapped-CSS edits and ordinary Astro caches may differ); packaged lifecycle (metacharacters, poisoned PATH, secret-free environments, child failures and teardown, timeout cancellation, ignored TERM/KILL, grandchildren, stale children, port collision, no automatic restart, complete reap or named failure); and Electron assertions (security preferences, sender checks, navigation allowlist, external-canvas edit disablement, popup/webview/permission/download denial, no iframe native IPC, no authority after renderer crash).
- Impact and confidence stay separate: remote native execution or silent cross-project writes are critical/high outcomes; registered-project config executing as the developer is the explicit trust premise, not a vulnerability.
